# V1 功能测试与回归用例

测试目标：验证用户能实际保存、关联、查看和追溯制作内容，而非只检查页面能打开。浏览器测试使用真实 Next.js API、PostgreSQL、Redis 与 OSS；故障页面使用定向 HTTP 拦截，明确与真实供应商验收区分。

## 浏览器用例

此外保留 `browser.spec.ts` 的全站基础冒烟测试，总计 20 个浏览器用例。

| 编号       | 操作                                              | 必须验证的结果                                                   |
| ---------- | ------------------------------------------------- | ---------------------------------------------------------------- |
| AUTH-01    | 错误密码、正确登录、退出、直接访问工作台          | 错误清晰；正确账号进入；退出后不能读取受保护内容                 |
| AUTH-02    | 邮箱大小写和首尾空格                              | 规范化邮箱，密码保持原样                                         |
| AUTH-03    | 显隐密码、本地入口提示、登录网关 502              | 正确显隐；本地标识与线上链接；错误可理解且可重试                 |
| FORM-01    | 逐字输入卖点并按 Enter                            | 换行不丢失；数据库保存为两条卖点                                 |
| FORM-02    | 输入未完成的 JSON 后保存                          | 无效时禁用保存，修正后才能提交                                   |
| PRODUCT-01 | 两位编辑者并发修改、版本历史、归档                | 旧版本不能覆盖新内容；冲突保留输入；历史和归档可找回             |
| FLOW-01    | 产品→批次→创意筛选→策划案→分镜→资产→脚本→视频审批 | 产品上下文不丢失；父子关联和资产版本正确；拒绝视频后没有生成任务 |
| BOARD-01   | 添加镜头、删除第一个、再新增                      | 镜号唯一，正常保存                                               |
| BOARD-02   | 10 个无图镜头拼接总览                             | 两页占位总览；来源版本准确；日志详情能显示两张结果               |
| FILE-01    | 浏览器上传文本                                    | OSS 文件、产品资料引用、新版本和异步解析文本均存在               |
| FILE-02    | 上传无音轨测试视频，建立成片                      | 无音轨不调用转写；视频可播放下载；缺少片段来源时明确标注         |
| SEARCH-01  | 创建 31 条创意、翻页、搜索最旧记录                | 全部可达，搜索查询所有记录而非当前页                             |
| GEN-01     | 切换只有特定模型的渠道和制作类型                  | 模型与渠道一致；无对应能力时不能提交                             |
| KEY-01     | 创建、限定产品/只读、复制、禁用、启用、轮换、撤销 | 各状态立即生效；Agent 不能管理 Key；复制过程不进入测试报告       |
| CHANNEL-01 | 创建隔离渠道、输入错误 JSON、禁用                 | 配置校验正确；普通响应不含凭据；不修改真实渠道                   |
| ROLE-01    | 只读成员登录与访问详情                            | 可读但无保存或生成入口；直接写 API 被拒绝                        |
| NAV-01     | 七个一级模块、日志、聊天面板、390px 手机布局      | 页面无未捕获异常；切换正常；无横向溢出                           |
| CHAT-01    | 真实 Agent 只读产品，刷新后查看                   | 工具读取正确产品；对话持久化；没有图片/视频/音乐任务             |

## 接口与任务补充验证

CHAT-02 额外模拟会话轮询返回 503，验证提示可见、无未捕获异常，并在服务恢复后继续读取会话。

- `tests/integration.ts`：身份、产品范围、成员权限、Key 到期/撤销/轮换、唯一分镜、版本冲突、视频禁止 Agent 自批、审批摘要篡改等 38 项断言。
- `tests/security.test.ts`：摘要规范化、加解密、日志脱敏等安全边界。
- `tests/recovery.ts`：并发锁、供应商提交状态、批次部分完成与审批快照等恢复边界，使用隔离的不可访问渠道，不购买生成。
- `agent/test_runtime.py`：Agent 工具路径白名单。

## 执行与数据隔离

```powershell
# 本地：使用 .env；需启动网站、Worker 和 Agent。
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npx playwright test

# 线上：仅从本地私有配置读取凭据，不把凭据写入测试文件。
$env:TEST_ENV_FILE = '.runtime/production.env'
npx playwright test tests/workflow.spec.ts

# 明确开启真实文本模型的只读 Agent 检查（会产生少量文本模型调用费用）。
$env:E2E_LIVE_AGENT = '1'
npx playwright test tests/workflow.spec.ts --grep CHAT-01
```

测试使用带唯一前缀的资料。每例结束后归档自身创建的资源、撤销测试 Key、停用测试成员和隔离渠道、拒绝遗留待审批批次；保留审计和版本，不删除真实业务数据或 OSS 对象。上传测试需要本地 ffmpeg 生成 1 秒静音黑色视频。

报告写入 `playwright-report/index.html`，失败截图位于 `test-results/`，均被 Git 忽略；不收集包含登录密码或 API Key 的网络 trace。不要把这些私有测试产物公开发布。测试报告中的通过只代表对应断言；真实视频生成、音乐供应商返回与取消确认仍需专门的付费验收，不将页面测试称为供应商全链路验收。
