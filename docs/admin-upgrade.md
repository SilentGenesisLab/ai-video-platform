# 管理后台与个人积分升级（1.4.0）

## 操作入口

平台管理员登录后，从工作台侧栏进入 `/admin`，可管理数据看板、模型渠道、用户和积分。后台接口只接受具备平台管理员权限的人类会话；团队管理员、普通成员与 Agent Key 均不能访问。

`/team` 保留团队成员、个人账号、个人钱包和团队公共池分配功能。个人积分余额全平台通用，团队公共积分分配后属于个人，退队不回收。调整积分必须填写原因，余额不能低于冻结额；转账在单一数据库事务内完成，并保留双方不可变流水。

## 模型采购价

人民币与积分换算为 1 元 = 100 积分。优先使用供应商明确返回的人民币费用，其次按请求所用的不可变采购价版本计算；缺价则每次供应商请求默认 1 元，标记为“临时估算”。后台可修改缺价默认金额；变更不改写历史费用。

供应商明确以参数、鉴权或限流错误拒绝接单时释放冻结。断网、响应中断及无法确认是否已接单的异常保留冻结并进入待对账，不自动重新购买；管理员取得账单或未计费证据后进行人工结算。

## 迁移和部署

新增个人钱包、个人不可变流水和全局计费默认值。既有用量保留原团队付款钱包，不迁移历史冻结或改写历史流水。新请求扣发起人的个人钱包，外部 Agent 扣 Key 所属用户，异步任务保存付款人。

上线迁移从 legacy-team 的可用公共余额向首位有效平台管理员分配最多 1000 积分，双方流水留痕，不增发。其他成员由团队管理员分配公共池积分。新注册用户的 1000 积分只赠送到个人钱包，新增团队不重复赠送。

部署先在独立目录构建，再暂停 web/worker/agent，备份 PostgreSQL、源码、配置和镜像标识，执行兼容迁移、价格初始化，然后启动服务。PostgreSQL/Redis 使用原卷，OSS 原文件不改动。

回退时先暂停新任务并核对新旧钱包的冻结记录，保留数据库备份；旧应用默认扣团队余额，不能在完成个人钱包迁移后直接长期运行。数据库灾难恢复需核对备份后业务，禁止自动覆盖线上数据库。
