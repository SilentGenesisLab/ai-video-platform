# Frameflow 1.1 · 官网、手机号、团队和积分

## 使用入口

- `/`：公开官网，示例产品与图形为原创虚构内容，不查询团队业务数据。
- `/login`、`/register`、`/reset-password`：邮箱兼容、手机密码/验证码登录、注册与重置。
- `/team`：团队切换、名称、邀请、成员、账号手机绑定、积分与用量；平台管理员额外可见采购价、全团队状态、积分调整与对账。
- Skill 1.1.0：`/skills/ai-video-platform/SKILL.md` 与 ZIP。已有 Key 自动回填原团队。

## 权限与迁移

`User.platformAdmin` 与 `TeamMember.role` 分离。原管理员保留平台身份，原团队数据统一回填 `legacy-team`；迁移仅发放一次 1000 分。新注册事务内建立用户、初始团队、所有者、钱包、唯一赠送流水。额外团队余额为 0。

业务请求使用 AsyncLocalStorage 固定团队并通过 Prisma 查询扩展过滤/标记全部业务模型。Worker 读取 Job 的固定团队后进入相同上下文。`systemDb` 仅用于鉴权、跨团队调度及受授权的平台管理。新增任何业务入口必须进入 `withTeam` 并检查所有对象引用归属。不要将原始数据库客户端用于普通业务读写。

Key 与 Agent Run 固定团队。当前成员权限、Key 状态在每次请求及后台付费提交前复核。不能删除/降级所有者。归档团队必须没有未完成任务、运行、待审批批次或冻结积分。用户归档还须保留另一个可用团队。

## 短信

私有服务端 `.env`：SMS_ACCESS_KEY_ID、SMS_ACCESS_KEY_SECRET、SMS_SIGN_NAME、SMS_TEMPLATE_CODE、SMS_REGION（cn-hangzhou）、SMS_CODE_VARIABLE（code）。不要把这些变量加 NEXT_PUBLIC 前缀。模板与签名须通过审核；部署前用 QuerySmsTemplate / QuerySmsSign 只读验证。

六位随机码，五分钟有效，按手机与用途隔离；存 HMAC 摘要，不保存明文。单手机 60 秒间隔、5 次/小时、10 次/日；单 IP 20 次/小时、100 次/日。最多 5 次校验错误，一次性消费。Nginx 必须覆盖 X-Real-IP，应用端口只绑定回环。供应商失败返回错误。没有生产万能验证码。

## 采购价与记账

1 人民币成本 = 100 积分。价格按渠道/模型/能力/规格/供应商/其他参数条件保存不可变版本；后台填写采购依据，生效时间自动记录。Token 输入、缓存命中、输出均按每百万 Token 录入；图片按张，视频按秒，音频可按请求。参数条件是匹配请求的 JSON 对象，例如 `{"sound":true}`。更具体条件优先。

空供应商价格必须是覆盖该渠道自动路由的合同采购价；有供应商专属价格时结算记录实际渠道和适用历史价格。不得虚构价格，缺价型号不可生成。预报价十分钟有效，包含参数、数量与采购版本。视频审批同时绑定生成快照与报价；过期或改价必须重新报价/提交审批，旧审批不能沿用。

钱包 PostgreSQL Decimal(20,6)，事务锁串行冻结/调整/结算；数据库约束确保余额与冻结非负且冻结不超过余额。积分流水和采购价数据库触发器禁止修改/删除。提交前冻结，每次实际调用独立用量。网页/Agent 的普通 CRUD 不收费。文本/识图经过业务计量服务；本地文档解析、分镜拼接和转存不收费。音视频转写必须配置对应型号及采购价，未配置时原文件保留并明确解析失败。

优先使用供应商明确的人民币账单费用；否则按用量及采购价计算并注明依据。费用未知、超额而余额不足或提交结果不明确时冻结保留、进入对账。后台只能在取得费用依据后结算，确认未收费填 0。模型结果缓存按调用 ID 防止重复购买；Worker 中断的提交不会自动再提交。文本估算使用保守 Token 上限，因此冻结额度可能高于最终扣分。

## 发布顺序和回滚

1. 在独立代码目录构建镜像；检查生产无在途 Job、Agent Run 和待审批批次。
2. 创建 root 私有 PostgreSQL 自定义格式备份，恢复至单独演练库。使用新镜像对演练库执行 migrate deploy，并核对产品/修订/文件数量、团队回填、成员、原钱包 1000 分和唯一赠送记录。
3. 进入短暂维护：停止本应用 web/worker/agent，保留 postgres/redis。再次备份，记录旧镜像及源码归档。
4. 用新镜像运行迁移及 seed，保留原有业务记录、OSS 和服务器私有配置；随后启动新 web/worker/agent。禁止新旧写入进程并行。
5. 验证 HTTPS、健康版本、旧邮箱登录、公开页面、团队钱包、Skill ZIP、关键权限。采购价为空时确认阻止生成。
6. 迁移失败且未恢复业务写入时，可恢复停写备份及旧镜像/源码。恢复写入后不可直接还原旧库丢弃新数据，先停止服务评估数据差异。

## 验证

`npm test`：凭据、权限和基础验证。
`npm run typecheck`、`npm run build`：类型及生产构建。
`npm run test:teams`：只允许本地 3002 / frameflow_teams 隔离库，覆盖两账号/团队、赠送幂等、引用隔离、API Key、邀请撤权、冻结并发、模型调用重放、费用未知、不可变流水、采购参数及短信生命周期。验证码夹具和供应商 mock 仅存在测试文件，不是应用后门。

浏览器需覆盖 390/768/1440 宽度、官网全部导航、登录注册、密码眼睛、团队设置。真实短信收发需用户指定测试手机号并输入收到的验证码。真实付费视频仍需人工审批。不要在测试中批量发送真实短信或替用户审批付费视频。

监控：内部 metrics、Job submission_unknown/transfer_failed、UsageRecord reconcile，以及积压 outbox。每日数据库备份与既有 HTTPS 证书续期继续使用。
