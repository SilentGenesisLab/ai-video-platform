# Creative detail pages

Plans and industrial storyboards use /studio/creative/plans/{id} and /studio/creative/storyboards/{id}; /new accepts productId, planId (storyboards), parentId (plans). The studio layout owns a persistent Workspace inside AssistantProvider so sidebar, topbar and chat survive navigation. List context is preserved per signed-in user/team in sessionStorage. Legacy ?id= resource links and generated-plan results navigate to detail pages; concepts retain their compact editor.

All long fields expand vertically; plan body toggles Markdown edit/preview, with readable preview default for read-only users. Every shot is expanded, reorder retains stable IDs and save renumbers positions. Pictures, candidates and version-bound asset references can be selected and inspected; uploads use existing signed storage APIs with parse skipped. Unchanged upstream references and revisions use the existing PATCH/baseVersion contract. Save remains on the detail page; new creation replaces /new with its canonical route. Conflicts retain local drafts and offer latest history or explicit discard/reload.

Unsaved edits prompt on back/list/sidebar/ordinary links and browser back; unload uses the browser's built-in prompt. Deletion archives through the existing versioned DELETE and retains downstream data. Main edits are inline, history is inline, and no paid task is triggered during acceptance. Tests cover long text, Markdown, stable sidebar, revisions, conflict preservation, cancel/accept navigation, direct/legacy links, new/save/reload, stable shot reorder and 390/768/1440px layouts. Existing server permissions/team boundaries remain authoritative; no schema migration.
